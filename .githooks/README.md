# Git Hooks

Custom git hooks for this repository, activated by setting `core.hooksPath`:

```bash
git config core.hooksPath .githooks
```

`make setup` does this automatically.

## pre-commit

Runs five steps on every commit to keep FFI crates, workspace versions, and generated bindings consistent.

### Steps

| # | Step | What it does | Exits non-zero when |
|---|------|-------------|----------------------|
| 1 | **Reject bindings edits** | Blocks staged changes under `bindings/` (except `bindings/README.md`) since those files are auto-generated by the release workflow | Any protected bindings file is staged |
| 2 | **Sync FFI versions** | Runs `scripts/sync-ffi-versions.sh` — when a lib crate version has changed relative to its last git tag, the corresponding FFI crate version is bumped (semver-aware) and the updated `Cargo.toml` files are staged | — (sync failures propagate) |
| 3 | **Check FFI coverage** | Runs `scripts/check-ffi-coverage.sh --cached` — verifies that staged lib source changes have corresponding FFI crate changes, and that minor/major lib bumps include `.rs` changes in the FFI crate's `src/` | Lib changes are missing FFI counterparts |
| 4 | **Sync workspace versions** | Runs `scripts/sync-workspace-versions.sh` — updates workspace dependency versions in the root `Cargo.toml` to match each crate's `[package].version`, then stages the file | — (sync failures propagate) |
| 5 | **Validate versions** | Runs `scripts/check-ffi-versions.sh` and `scripts/check-workspace-versions.sh` to assert that all FFI versions are ≥ their lib counterparts and that workspace dependency versions match crate versions | Any version is misaligned |

### Environment variables

| Variable | Default | Effect |
|----------|---------|--------|
| `SKIP_BINDINGS_CHECK` | _(unset)_ | Set to `1` to skip step 1 (reject bindings edits) |
| `SKIP_FFI_COVERAGE` | _(unset)_ | Set to `1` to skip step 3 (FFI coverage check) |
| `GITHUB_ACTIONS` | _(unset)_ | When set (automatically true in GitHub Actions runners), all log output from the hook and its subscripts is prefixed with GitHub Actions workflow commands (`::error::`, `::warning::`, `::notice::`, `::debug::`) so messages appear as annotations in the Actions UI. When unset, messages use emoji-only prefixes. |

### Examples

```bash
# Normal commit — all checks run
git commit -m "update core"

# Skip the bindings guard (e.g. when regenerating bindings locally)
SKIP_BINDINGS_CHECK=1 git commit -m "regenerate bindings"

# Skip FFI coverage check (e.g. docs-only change in a lib crate)
SKIP_FFI_COVERAGE=1 git commit -m "fix doc comment"

# Skip both
SKIP_BINDINGS_CHECK=1 SKIP_FFI_COVERAGE=1 git commit -m "wip"
```
